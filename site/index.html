First, Turn On Active AI

An Owner does this once for the firm in Active, whichever agent you use.

1. License Users

In user and licence management, tick Active AI for each person who'll use an agent. No Active AI module? Your firm isn't licensed yet, so get in touch.

2. Turn On The MCP Server

In Admin Centre > AI Settings, turn on the MCP server. It's a Preview feature: read the terms on that screen first, because you're approving Preview access for your firm.

Choose Read-only or Read and Write as the default. Tool overrides always allow or always block single tools. Only an Owner can change these settings.

How It Works

Your Login. Your Access. Your Approval.

Every agent connects to the same Active server, and every person signs in as themselves. The agent can never do more than you can.

Your AgentClaude, Copilot Studio and othersCalls Active tools over MCP
Active Sign-InYour own Active loginChooses the firm and grants a token
Active MCP ServerChecks your access on every callApplies your firm's licence and rules
ActiveClients, documents, workpapersOnly records you can open

Sign In With Active

Each person signs in with their own Active login the first time the agent needs it. There are no API keys or shared secrets to pass around.

Only What You Can See

The agent sees the clients, documents and workpapers you can see in Active. Your firm's Active licence decides which tools it gets.

Changes Need Your OK

Tools that create or change records act on live data. Set up your agent to show what will change and ask before it runs them.

Quick Start

Copilot Studio has two kinds of agent, and they add Active in slightly different places. New agent creates the newer kind. Agent (Standard) is under the arrow next to it. Pick yours:

You'll paste these three values when you add Active. The agent reads the description to decide when to call Active, so paste it as written.

Server name
Active
Server description
Active is the practice platform for accounting firms. Use these tools to find and update clients, client groups, offices and people; search, upload and version client documents; and work with Active Workpapers binders, trial balances, worksheets and client queries.
Server URL
https://mcp.businessfitness.com/

  1. Create the agent

    In Copilot Studio, go to Agents and select New agent. Type a name over Untitled Agent at the top of the page.

  2. Add the Active server

    1. On the right of the Build page, select + next to Tools.
    2. In Add a tool, select + Add, then Model Context Protocol (MCP).
    3. Paste the server name, description and URL from above.
    4. For Authentication, select OAuth 2.0. Leave Configuration type on Dynamic (with discovery).
    5. Select Add. Copilot Studio registers itself with Active, which takes up to 30 seconds.

  3. Connect your Active account

    1. In Select a connection, open the Not connected list and select Create new connection, then Create.
    2. A pop-up window opens at identity.businessfitness.com.au. Select Sign in with Microsoft, or enter your email and select Next.
    3. If your login belongs to more than one firm, choose the firm.
    4. Active asks whether Credential Manager can access your Active account. Select Allow access.
    5. Back in Copilot Studio, the connection shows Active. Select Add.

    The sign-in opens in a pop-up. If nothing opens and Copilot Studio shows Deleting connection, allow pop-ups for copilotstudio.microsoft.com and select Create again.

  4. Add instructions, save and test

    1. Paste the agent instructions into Instructions on the Build page.
    2. Select Save in the top bar. The first save takes about 30 seconds.
    3. Open the Preview tab and ask:
    Who am I?Who am I, and which offices and teams do I belong to?

    The answer shows Used tool: active-core-me-get, then your name, role, offices and teams from Active.

  5. Publish to your team

    Select + next to Channels on the Build page to add Teams and Microsoft 365 Copilot, then select Publish. Each person signs in to Active the first time the agent needs it, and sees only their own Active access, as long as the Active tool uses end-user credentials.

Active already added in your environment? Copilot Studio saves the server for the whole environment, so adding it again fails with A custom connector with display name 'Active' already exists in the environment. Instead, in Add a tool, filter by Model Context Protocol and pick Active.

Why does it say Credential Manager? That is the name Copilot Studio registers under when it connects to Active. The access screen also says access goes to global.consent.azure-apim.net, which is Microsoft's sign-in service for Power Platform connectors. Both are expected. Leave the access boxes ticked: the agent's tools need them, and your Active licence still limits what it can do.

Tips

  • Leave the Active tool's Authentication setting on End user credentials, the default. With Maker-provided credentials, everyone who uses the agent acts in Active as you, and can see and change anything you can.
  • Keep the server description specific. Copilot Studio uses it to decide whether a question is for Active.
  • Turn off web search so answers about clients come only from Active: remove Search all websites under Knowledge on a new agent, or turn off Web Search on a Standard agent's Overview.
  • On a Standard agent, open the Active tool to switch single tools on or off. For a read-only agent, turn off the tools that create, update, upload or delete.
  • The agent only gets the tools your Active licence allows. People with different licences can see different tools in the same agent.
  • Test with a login that has the same access as the people who will use the agent, not only an administrator.
  • Name clients in full. "Acme Pty Ltd" finds one client faster than "Acme".

FAQ

Do I need a client ID or secret from Active?

No. With Dynamic (with discovery), called Dynamic discovery on a Standard agent, Copilot Studio reads Active's sign-in details from the server and registers itself. Active only accepts these registrations from Copilot Studio's own sign-in callback.

What can the agent see?

Only what the signed-in person can see in Active. Every call is checked against that person's access and your firm's Active licence. Someone who can't open a client in Active can't reach it through the agent either. This holds while the Active tool uses end-user credentials, the default. If the maker switches it to their own credentials, everyone acts as the maker.

Can the agent change records in Active?

Yes, if your licence includes the tools that create and update records. Those tools act on live data. Use the agent instructions above so the agent asks before it changes anything, or turn the tools off for a read-only agent.

Which firm does the agent connect to?

The firm you choose when you sign in. Each person who uses the agent signs in and chooses for themselves. To change firm, delete the connection and sign in again.

Do our data policies apply?

Yes. Copilot Studio reaches MCP servers through Power Platform connectors, so your environment's data policies govern the Active connection. Ask your Power Platform admin to place it in the right data policy group.

How do I disconnect?
  • Remove the Active tool from the agent, or delete the connection in Power Platform.
  • To revoke access from Active's side, open Connected Apps in your Active account and remove Credential Manager, the name Copilot Studio uses.

Troubleshooting

No tools appear after I add Active
  • Check the server URL is exactly https://mcp.businessfitness.com/, starting with https.
  • Make sure you selected Add (or Add and configure) after the connection showed Active.
  • On a Standard agent, open the Active tool and select Refresh connector.
Copilot Studio can't create the tool

Check that Authentication is OAuth 2.0 and the type is Dynamic (with discovery) or Dynamic discovery. The Dynamic and Manual types need details Active doesn't hand out. If it still fails, contact Active support with the time you tried.

"A custom connector with display name 'Active' already exists"

Someone already added Active in this environment, and Copilot Studio keeps one per name. Go back to Add a tool, filter by Model Context Protocol and pick Active from the list.

Nothing opens when I create the connection

The Active sign-in opens in a pop-up window. If your browser blocks it, Copilot Studio shows Deleting connection and stops. Allow pop-ups for copilotstudio.microsoft.com and select Create again.

The sign-in window shows an error

Close the window and select Create a new connection again. If the error repeats, note the message and contact Active support. Signing in to Active in another browser tab first can help if your session has expired.

Some tools are missing

Your firm's Active licence, your own access and your firm's AI Settings decide which tools you get. Tools that change records need write access. Ask your Active administrator what your firm has turned on.

The connection is blocked by a data policy

Your environment's data policy doesn't allow the connector. Ask your Power Platform admin to allow it, or build the agent in an environment where it's allowed.

FAQ

What does the plugin add?

The connection to the Active server, plus skills that teach Claude how to work with Active: finding clients and documents, moving documents in and out, and the Workpapers client-query workflows.

Should I add Active as a connector, or with claude mcp add?

No. The plugin adds the Active server, and one you add by hand replaces the plugin's. In Claude Code, remove a hand-added one with claude mcp remove <name>.

What can Claude see?

Only what the signed-in person can see in Active. Every call is checked against that person's access and your firm's Active licence.

Which firm does Claude connect to?

The firm you choose when you sign in. In Claude Code, to switch, sign in to the Active server again from /mcp and choose the other firm.

Does turning off network egress block Active?

No. Network egress and the domain allowlist apply to Claude's code sandbox, not to MCP connectors. Control what agents can do in Active, under AI Settings.

Troubleshooting

Active's skills don't run in the Claude app

Turn on Cloud code execution and file creation in Organisation settings > Capabilities. The skills need it.

Document upload or download fails in the Claude app

Add the allowed domains, and check Allow network egress is on.

The Claude app says Active isn't connected

An admin opens the Active Platform plugin, goes to the Connectors tab, and connects active-mcp again.

The Active tools don't appear in Claude Code

Run /reload-plugins, or restart Claude Code. Then check /mcp lists the Active server. If it shows Active as failed or needing sign-in, choose it and sign in again.

The browser shows a sign-in error

Close it and sign in again. If the error repeats, note the message and the time, and contact Active support.

Some tools are missing

Your firm's Active licence, your own access and your firm's AI Settings decide which tools you get. Tools that change records need write access. Ask your Active administrator what your firm has turned on.

FAQ

Do I need codex mcp add?

No. The plugin adds the Active server. If you added Active by hand before, remove it with codex mcp remove <name> so Codex doesn't have it twice.

Do I need a client ID or API key?

No. Codex identifies itself to Active with client details that OpenAI publishes, and you sign in with your own Active login.

What can Codex see?

Only what you can see in Active. Every call is checked against your access and your firm's Active licence.

Will Codex ask before it changes records?

Tools that create or change records act on live data. Codex's approval settings decide whether it asks before it runs a tool, so keep approvals on for Active.

How do I get plugin updates?

Run codex plugin marketplace upgrade to refresh the Active marketplace, then restart Codex.

How do I disconnect?
  • Remove the plugin from Settings > Plugins, or run codex plugin remove active-platform@active.
  • To revoke access from Active's side, open Connected Apps in your Active account and remove Codex.

Troubleshooting

Sign-in fails, or mentions client registration

Run codex mcp login active-mcp --oauth-client-registration cimd, which tells Codex to sign in with its published client details. If it still fails, note the message and the time, and contact Active support.

The browser can't get back to Codex after sign-in

Another program may be using the port Codex listens on. Set mcp_oauth_callback_port to a free port at the top of config.toml, then sign in again.

Active doesn't appear after installing

Restart the Codex app, or select Restart extension in the IDE. Both read plugins only when they start.

Some tools are missing

Share With Your Workspace

Only you can use Active until a workspace admin or owner publishes it.
